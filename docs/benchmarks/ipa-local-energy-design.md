# IPA Grid Local Energy的同图安全适配

## 需求与范围

用户要求与既有benchmark输入一致，并确保最终全局路线不碰撞。沿用既有三张PNG、阈值、float32的0.05 m分辨率、公共起点、作业宽度0.6 m、中心净空1 m、原图全部已知自由像素分母。现有五种实现及历史15组证据保持不变；新增 `IPA Local Energy＋A*` 进入六列总览，原生输出另作诊断，避免将访问顺序误作安全折线。

本次是离线栅格几何规划；只在已知地图/共同净空模型内保证完整线段可行，不代表动态障碍、定位误差、曲率、连续机器人footprint或真机执行验收。

## 上游与边界

- 上游 `ipa320/ipa_coverage_planning` 的 `noetic_dev`，固定 `986c18384ed884dadd3bc857cd0c47c13b7d4716`；原文件保留，记录原始与实际编译源码、可执行文件、编译器和动态库SHA。
- 使用 `EnergyFunctionalExplorator::getExplorationPath`，保留原生房间旋转、格点生成、能量评分、访问顺序及半格内缩。footprint模式的格距为 `coverage_radius*sqrt(2)`，覆盖半径为0.3 m；不能把0.6 m作业宽度误当原生格距。
- 自有C++入口将共同起点净空分量转换为左下原点的二值栅格；像素索引坐标以半格平移映射到共同像素中心。调用footprint模式；ROS消息/日志用薄兼容头，未支持的FOV分支显式拒绝，不迁移整套ROS 1执行器。
- 原生额外半格内缩属于内部预处理，可能减少规划范围；输入/输出格距、原生点数、共同可达分量大小与完整原始点序列均记录。公共净空不放宽。

## 安全连接

1. 共同起点必须属于共同净空栅格；仅取其四邻接分量，不借助不可达分量增加名义覆盖率。
2. 原生所有输出点必须有限、落在该分量，按原顺序逐一保留；不移动、裁剪或删点。不满足则最终规划失败。
3. 从共同起点开始，对每个目标调用已有 `GridConnector.connect`：直线无切角可行则保留，否则在原分辨率共同净空图上8邻接A*，禁止对角穿角，简化后的连接再次检查。
4. 最终对每条边检查原图、共同净空及闭格接触；不可达/违规则返回空最终路线，原生诊断和错误仍保留。所有原生目标的访问顺序及连接区间可重放。
5. 复用公共三项指标，完整路径计入起点接近、绕障和重复移动，不要求额外回起点；该终点规则与F2C修改版一致，ETHZ闭合规则仍单独标注。

## 模块与验证

自有模块：`ipa_build.py`负责固定上游/构建与指纹，`ipa_native/`提供headless入口及兼容头，`ipa.py`负责输入、原生进程和规划编排，`ipa_connection.py`负责逐段安全组装和严格审计，`ipa_compare.py`负责新三图及六列总览，`verify_ipa.py`负责独立证据重放。

测试先观察缺失行为失败，再实现：带孔原生调用与不改源文件；完整原生目标顺序保留；跨墙绕障；对角接触/不可达/非法起点失败；真实超时/中断清理；构建缓存与证据篡改拒绝。真实三图保存输入、原生原始输出、日志、修复后完整路径、逐段来源和指纹；独立复核逐点重放、公共三指标、全部连接及独立扫掠见证。
